### CLI discovery, jobs, and vector search

Better Fullstack 2.8.0 adds ways to explore the option catalog, generate background workers, and build vector search. Go gets job scheduling and migration tools. Python gets request-aware logging. This release also fixes authentication, production startup, and deployment in generated projects, and adds guides and starter pages across ecosystems.

### Explore the catalog from your terminal

- **List and search options.** The new `list` and `search` commands let you browse the catalog without stepping through project creation. Discover categories, ecosystems, supported examples, and aliases, with JSON output for scripts and agents.
- **Explain a choice.** The new `explain` command describes an option's requirements and exclusions, including the shared compatibility rules behind them. The explanation is also available through MCP.
- **Complete commands and values.** Generate completion scripts for Bash, Zsh, Fish, and PowerShell. Completion covers command names, flags, allowed values, `--flag=value`, list selections, and fixed positional choices.

### Background jobs in TypeScript and Go

- **pg-boss, Upstash QStash, and Hatchet** join the TypeScript job queue options, with generated enqueue code, workers, environment configuration, and build wiring. The builder and CLI reject unsupported runtime and deployment combinations. pg-boss projects declare the Node version they require.
- **River and gocron** join the Go options. River provides PostgreSQL-backed jobs; gocron provides scheduled jobs. Generated projects include worker or scheduler setup and shutdown handling.
- **Deployment follows the queue.** Worker-capable deployment choices are filtered to match the selected queue. Docker server services receive the environment their queue integration needs, including the Hatchet token.

### Four more vector databases

Choose **Weaviate, Upstash Vector, turbopuffer, or LanceDB** for TypeScript vector search. The generator supplies the selected integration and its configuration, while the CLI, stack graph, and builder apply its compatibility rules.

### Go migrations and Python logging

- **Goose and Atlas** add migration workflows to Go projects. Generated commands and configuration use the same database as the server, including the SQLite file path. Unsupported database, ORM, and migration combinations are rejected before generation.
- **Loguru and structlog** add a Python logging category. Generated web projects get request context and error logging across development and production run modes. Streaming failures propagate after a response has started, rather than trying to append a second error response. Logging requires a Python web framework.

### Authentication that reaches the generated API

- Fullstack **Nuxt** projects mount **Better Auth and oRPC** through Nitro routes, and redirect signed-out visitors from protected pages to login. The Nuxt guide now matches the generated Prisma project.
- Generated **Clerk and Auth.js** projects expose the signed-in user to their API layer. Auth.js sign-up, password handling, and dependency wiring are corrected.
- Generated **AI endpoints** require a signed-in user when supported authentication is selected, with checks against cross-site and cross-user use.
- **Better Auth dependency families** stay on one release across creation, addition, and updates, including workspace catalogs and version channels. Generated npm projects install one Better Auth core.
- Requested authentication is rejected when the selected ecosystem, backend, database, or ORM cannot wire it. Conflicting providers and impossible database/ORM pairs are checked consistently across the CLI, builder, graph, virtual generation, and update planning. Go Better Auth selections survive multi-ecosystem composition.

### Generated apps start and deploy more reliably

- **TanStack Start** production builds serve requests without the startup crash fixed in this release. Generated TypeScript servers and their shared Docker image start correctly, including Prisma and AdonisJS projects.
- **Expo** templates use a consistent **SDK 56** dependency set that installs with npm. Native Hono/tRPC presets include and type-check their server.
- **Phoenix** projects boot and build production releases. LiveView pages are interactive, session routes reject cross-site forms, and Oban database upgrades and formatter output are corrected.
- **Fly.io** deployment configuration resolves its Dockerfile from the configuration directory. Go deployment images use the reviewed **Go 1.26** toolchain.
- **Project updates** retain template baselines and synchronized dependency families, including dependencies stored in workspace catalogs.
- Generated project dependencies and the repository toolchain are updated. The website moves to the TanStack Start version needed for its Vercel deployment.

### More ways to choose and learn a stack

- New starter pages cover **Java, Kotlin, .NET, Elixir, and Expo**, plus **15 more TypeScript combinations**, including Convex, Nuxt, SvelteKit, NestJS, and Cloudflare Workers.
- New guides cover **Elysia, Fastify, Convex, and Angular**, alongside **Phoenix, .NET, Ktor, Quarkus, and Expo**. Three use-case guides walk through **browser extensions, desktop apps, and e-commerce stores**.
- New comparisons cover **14 scaffolding tools** across JavaScript and other ecosystems. Nine articles compare API layers, backends, authentication, validation, Python, Rust, Go, Java, and server runtimes.
- Every docs page has a reader-language route with English fallback where a translation is pending. Markdown source links point to their HTML pages, and the shared stack builder stays out of search results.
- A public **changelog page** collects published releases, with a Markdown copy for agents and links to each GitHub release. The builder also gets clearer opt-outs beside subsection titles.
